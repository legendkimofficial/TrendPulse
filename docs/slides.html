감쇠 윈도우로 순위, DGIM으로 보조 집계

감쇠 윈도우 + 제거 주 기능

score(w) ← score(w)·(1−c) + 1[w ∈ 새 기사]
  • c = 0.001: 영향이 693건마다 절반(반감기). 경계 있는 창이 아니며 최근 1,000건이 가중치의 63%
  • 점수 < θ(0.5) 키워드는 삭제, 잃는 점수 < θ/(1−θ)
  • 전체 감쇠는 전역 계수 하나로 O(1). 기사당 비용은 토큰 수만큼의 갱신 + 힙 관리

DGIM 보조 기능

최근 N개 기사 중 키워드 등장 기사 수 ≈ ?
  • 크기 2k 버킷, 크기별 최대 r개, 상대오차 ≤ 1/(2(r−1))
  • Top K 진입 시 자동 추적, 추적 시작 이후만 계수 → 화면에 "관측 n/N건"
  • 용량 300개: 현재 Top K·사용자 고정은 유지, 오래 비활성인 자동 추적부터 교체

단위 테스트 33개: 단순 구현과의 일치, 오차 상한, 추적 용량 정책, 잘못된 설정 거부, Solar 근거 검증(mock)

실험 4 · DGIM (보조 기능)

DGIM의 이득은 "무엇으로 재느냐"에 따라 달라진다

논리 저장량(압축 가정)으로는 N=500에서 DGIM이 103%로 손해, N=5,000에서 39%로 이득. Python 실측으로는 모든 구성에서 DGIM이 더 작음(34~85%) — 정확 쪽 deque의 고정 비용 때문. 두 수치를 섞지 않는다

오차는 모두 이론 상한 안. 중앙값 추정의 평균 오차 7.9% vs 교과서식 26.7%는 등장 1~4회에서 생긴 차이(6.4% vs 32.2%). 10회 이상은 11.0% vs 11.1%, Top 10 겹침도 같음
