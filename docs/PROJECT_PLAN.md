# Trend Pulse 구현 및 검증 계획

Trend Pulse는 GDELT Article List(GAL)에 수록된 여러 나라 언론사의 영어 기사 제목에서 화제 키워드를 추출한다. 기본 화면은 최근 7일 감쇠 순위와 보도 매체·발행국 수를 보여준다. 72시간 화면은 직전 72시간과 비교해 보도 비중이 증가한 키워드를 보여준다.

필수 제출 범위는 연속 7일의 고정 데이터 재생, 7일 순위, 72시간 급상승, 감쇠 윈도우 및 DGIM 비교 실험, 실제 Upstage Solar 시연이다. 주기적 기사 수집은 추가 목표이며, 30일 추이는 후속 범위다. 고정 재생과 주기 수집은 같은 기사 형식과 집계 코드를 공유한다. 주기 수집에는 신규 배치 판별, 재시도, 재시작 지점 저장, 중복 방지, 마지막 성공 시각 표시가 추가된다. 시연용으로 실행 중에만 갱신하는 범위면 수집기 확장으로 처리할 수 있다.

## 구현 에이전트에 전달할 프롬프트

Trend Pulse의 GDELT 기반 제출 버전을 구현하고 검증해줘. 시작점은 이 계획이 담긴 `project-plan` 커밋이다. 코드는 그 커밋에서 별도 구현 브랜치로 분기해 작성해. Git 작성자와 GitHub 인증은 `apple4232`를 사용하고, 변경은 로컬 구현 브랜치에 남겨. 기존 HuffPost 재생과 실험은 회귀 확인에 사용해. 코드 작성 전에 `README.md`, `PROGRESS.md`, `trendpulse/data.py`, `trendpulse/engine.py`, `trendpulse/decaying.py`, `trendpulse/dgim.py`, `trendpulse/agent.py`, `app.py`, `experiments/`, `tests/`의 현재 동작과 기대값을 확인해.

### 1. GAL을 수집하고 고정 재생 입력을 만든다

- `scripts/`에 GAL 수집 명령을 추가하고, `trendpulse/data.py`에서 데이터 출처를 명시적으로 선택하도록 해. 완료된 UTC 기준 7일 구간의 시작과 끝을 고정해. 기사 제목, 짧은 설명, URL, 도메인, 매체명, 언어, 배치 관측 시각을 보존해. 발행 시각과 배치 관측 시각을 구분하고, 재생은 관측 시각과 고정된 동률 정렬 키로 결정해.
- 영어 기사만 분석에 사용해. 우선 미국·영국·캐나다·호주·인도·한국의 후보 매체를 검토하고, 확인 가능한 도메인과 발행국 매핑을 버전 관리해. 수록량을 확인한 뒤 최종 매체 목록과 제외 이유를 기록해. 발행국은 언론사 기준으로 분류하고 매핑이 불명확한 도메인은 별도 집계해.
- URL 중복은 정규화 규칙을 명시하고, 서로 다른 매체의 별도 보도는 구분해. 파일 미제공 응답, 네트워크 실패, 파싱 실패를 각각 기록해. 정상 배치가 전혀 없는 시간과 수집 실패를 보고하고, 공백이 있으면 지표 계산 가능 구간을 명시해.
- 고정 입력의 해시, UTC 기간, 원시·정제·제외 건수, 일별·매체별·발행국별 기사 수를 보고서에 남겨. 같은 입력을 두 번 재생했을 때 기사 순서가 같아야 해. 원시 데이터와 인증 정보는 Git에 추가하지 말고 GDELT 출처를 표시해.

### 2. 7일 감쇠 순위와 72시간 급상승을 구현한다

- 재생 시각을 `t`로 두고 7일 순위에는 `(t - 7일, t]`에 관측한 기사만 반영해. 기사 제목에서 추출한 키워드는 기사당 한 번만 세고, 각 기여분에 경과 시간 기준 지수 감쇠를 적용해. 반감기 48시간을 초기 실험값으로 두고 설정에 기록해. 같은 시각에 들어온 기사, 긴 관측 간격, 7일 경계의 포함·제외와 동률을 검증해.
- 작은 입력에서 기사별 가중치를 직접 합산한 값으로 기준 계산의 정확성을 검증해. 기존 감쇠 구현을 가능한 범위에서 활용하고, 7일 만료 처리와 키워드 제거를 설계해. 제거한 키워드의 이전 기여분을 만료 시 다시 차감하는 오류가 없는지, 재등장 후 점수가 올바른지 확인해. 이전 구현의 오차 상한은 새 만료 방식에도 적용된다는 근거가 있을 때 보고해.
- 72시간 급상승은 최근 `(t - 72시간, t]`과 직전 `(t - 144시간, t - 72시간]`을 비교해. 각 구간에서 키워드 포함 기사 수를 해당 구간의 전체 분석 기사 수로 나눠 보도 비중을 계산해. 비중 차이를 기본 점수로 사용하고, 최소 기사 수와 매체 수는 설정으로 공개해. 6일의 유효 관측 범위가 확보되기 전이나 분모가 0인 경우는 계산 가능 상태를 명시해. 신규 Top K 진입과 보도 비중 상승은 각각 표시해.
- 웹에서 7일 순위와 72시간 급상승을 조회할 수 있게 하고, 키워드를 선택하면 기준 시각까지 관측한 근거 기사, 매체 수와 발행국 수를 표시해. 7일 순위는 7일 자료가 확보된 시점부터 표시하거나 부분 집계임을 명시해. 화면과 API가 같은 시각과 정의를 사용하도록 해.

### 3. 감쇠 윈도우와 DGIM을 비교 검증한다

- 같은 GAL 입력·반감기·7일 범위·키워드 규칙에서 전체 키워드 유지 방식과 낮은 점수 제거 방식을 비교해. Top K 구성원 일치율, 점수 오차, 신규 진입 누락·지연, 저장 키워드 수, Python 집계 자료구조 크기, 입력 처리와 조회 시간을 기록해. 만료 처리에 필요한 상태는 비용에 포함하고, 원문 저장과 기사 조회 인덱스는 집계 비용과 별도로 보고해.
- 고정된 시각에 순위를 측정해 재실행 간 결과를 맞춰. Top K 진입 지연의 단위와 스냅샷 간격, 비교 종료까지 미확정인 사례의 처리 방식을 기록해. 계산 방식끼리의 일치율과 실제 화제 사례 검토를 구분해.
- DGIM은 선택한 키워드를 추적하기 시작한 뒤의 최근 N개 기사에 적용해. 같은 시작점에서 효율적인 정확 슬라이딩 집계와 대조해. 등장 0건, 추적 초기, 경계 만료, 버킷 병합을 작은 입력으로 확인하고, GAL 재생에서는 절대 오차, 실제 횟수가 양수인 경우의 상대 오차, 버킷 수, 논리 비트 수와 실제 객체 크기를 보고해. 72시간 집계와 최근 N개 기사 추정치는 화면에서 기준을 각각 표시해.
- 기존 `experiments/`의 실험 코드를 재사용해 같은 명령으로 입력과 결과를 다시 만들 수 있게 해. HuffPost 수치를 GAL 결과로 옮겨 적지 말고, GAL 입력이 없으면 합성 검증과 실제 데이터 실험의 상태를 구분해.

### 4. 실제 Solar 응답과 시연을 확인한다

- `trendpulse/agent.py`와 평가 코드에서 데이터 출처와 재생 시각을 현재 입력에 맞게 전달해. 환경에 설정된 Upstage 키로 실제 호출을 실행하고, 통계 및 관련 기사 도구 호출, 답변의 수치와 기사 ID가 조회 결과에 부합하는지 확인해. API 키를 출력하거나 저장하지 말고, 성공·오프라인 대체·오류를 결과에 구분해.
- GDELT 순위에서 고른 이슈로 관련 기사와 원문 링크를 확인하고, Solar 설명이 같은 시점의 기사에 근거하는지 점검해. 키가 없거나 호출에 실패하면 실제 Solar 검증을 미완료로 보고하고, 오프라인 시연 결과를 따로 기록해.
- 새 환경에서 README로 고정 입력 준비, 전체 테스트, 앱 실행, 실험 재현을 수행해. 경계 처리, 순위 변화, DGIM 정확 기준, API와 웹 화면의 일치 여부를 확인해. 실행 명령, 입력 해시, 비교 결과, 시연 기록, 실패 또는 미실행 원인을 남겨.

### 5. 필수 범위를 통과하면 주기 갱신을 추가한다

- 같은 수집기를 재사용해 새 GAL 배치를 주기적으로 가져오는 시연 모드를 추가해. 마지막으로 처리한 지점, 재시도 상태, 지연 도착 배치의 처리 규칙을 기록해. 같은 배치를 다시 받거나 중간에 재시작해도 동일 URL을 두 번 집계하지 않는지 확인해.
- 시연 화면에 마지막 성공 시각을 표시하고, 새 파일이 없거나 수집이 실패해도 마지막 정상 결과를 확인할 수 있게 해. 고정 재생 입력과 갱신 중인 입력을 구분해 시연과 실험 결과의 재현성을 유지해.

최종 보고에는 **변경 파일, 실행한 명령, 결과 파일, 항목별 통과·실패·미실행 상태**를 적어. 제출 성공 기준은 고정 GDELT 입력에서 7일 순위와 72시간 급상승을 재현하고, 비교 실험과 실제 Solar 도구 호출의 증거를 제시하는 것이다.
