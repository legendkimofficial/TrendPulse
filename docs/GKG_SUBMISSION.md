# Trend Pulse — GKG 브랜치 제출 문서

브랜치 `gdelt-gkg`. 키워드 목록 없이 GDELT GKG 2.1 영어 기사 흐름에서 **7일 주요 이슈**, **72시간 신규 이슈**,
**30일 반짝·꾸준**을 시간 감쇠 윈도우(교재 §4.7)로 찾고, 낮은 점수 삭제(θ)가 메모리·순위·신규 포착에 주는
영향을 측정한다. 모든 수치의 출처는 `experiments/results/gkg/` 아래 JSON과 `summary.md`다.
확인하지 못한 값은 **[미확인]**으로 표시했다.

## 1. 환경

- Python 3.14.5 (Windows 11)에서 확인. 표준 라이브러리(sqlite3 포함) + `requirements.txt`(flask, matplotlib)만 사용.
- 무작위성은 E5 빈 슬롯 제거뿐(시드 20241001, results.json 에 기록). 결과 JSON에 git 커밋(실행 시작 시), 코드 파일 SHA-256, 입력 해시를 기록.
- 에이전트: 환경변수 `UPSTAGE_API_KEY`가 있으면 Upstage Solar, 없으면 오프라인 요약.

## 2. 재현 명령

```bash
# 0) 데이터 (재개 가능, 61일 × 96개 15분 파일; 원본 zip은 저장하지 않음)
python scripts/gdelt_download.py --start 2024-09-15 --end 2024-11-14

# 1) 입력 점검: 기사 수, 빠진 슬롯, 중복 URL, 버린 키, 스트림 SHA-256
python scripts/gkg_build.py --start 2024-10-01 --end 2024-10-01

# 2) 엔진 재생: 세 창 Top 10, 키 수, 메모리, 처리 속도, 판별 결과
python scripts/gkg_run.py --start 2024-10-01 --end 2024-10-01
python scripts/gkg_run.py --start 2024-09-15 --end 2024-11-14 --windows 72h --theta 0.5   # 창·θ 하나씩

# 1b) 61일 입력 점검 (2024-10-01 manifest 를 덮어쓰지 않도록 하위 폴더에)
python scripts/gkg_build.py --start 2024-09-15 --end 2024-11-14 --out experiments/results/gkg/manifest_61d/input_manifest.json

# 2b) 실험 E1–E5 (61일, 약 2시간) / E2만 다시 (약 1시간)
python experiments/run_gkg_experiments.py
python experiments/run_gkg_experiments.py --only E2

# 3) 대시보드 캐시 기록 + 실행 (포트 5002; 같은 범위면 캐시 재사용)
python scripts/gkg_app_cache.py --start 2024-09-15 --end 2024-11-14
python scripts/gkg_app_cache.py --start 2024-09-15 --end 2024-10-14
python scripts/gkg_app_cache.py --start 2024-09-15 --end 2024-10-14 --theta 0.5   # 설정에서 고를 θ 변형
python app_gkg.py --start 2024-09-15 --end 2024-11-14

# 4) 테스트
python -m unittest discover -s tests
```

## 4. 방법 요약

| 구성 | 내용 |
|---|---|
| 감쇠 창 | 키마다 실수 하나. 점수 = Σ 2^(−(t−ts)/h), h = 72·168·720시간. 전역 기준 시각으로 O(1) 갱신, 2의 거듭제곱 재기준화 |
| 증분 Top K | 이전 Top 2,000 ∪ 지난 스냅샷 이후 갱신된 키만 정렬. K ≤ 2,000에서 전체 정렬과 같음(테스트) |
| θ 삭제 | 스트림 시간 6시간마다 점수 < θ 키 삭제, 다시 나오면 0부터(항상 과소추정). θ=None이 정확 기준 |
| 보정 보도율 | 점수 × ln2/h ÷ (1 − 2^(−경과/h)) [건/시간] |
| 72시간 신규 | lift = (r72+1)/(r168+1), 후보 72h Top 2,000, 최근 72시간 기사 ≥ 20·언론사 ≥ 5, Top 10, 진입 이벤트 |
| 30일 반짝·꾸준 | ratio = (r168+1)/(r720+1), F = 1.5: ≥1.5 최근 급증, 1/1.5~1.5 꾸준, <1/1.5 식는 중. 대시보드는 168h Top 2,000 후보를 라벨별 3칸(급증 ratio 큰 순, 식는 중 ratio 작은 순, 꾸준 168h 점수순, 각 10개)으로 표시 |
| 준비 기간 | 신규 7일, 반짝·꾸준 21일 (수학적 상한 때문, §6) |
| 빈 구간 | 창별 최근 구간의 빠진 15분 슬롯 비율, 5% 초과 시 "근거 부족"으로 보류 |
| 근거 저장 | 어느 창이든 Top 200에 든 키만, 키마다 UTC 하루 30건까지 sqlite에 저장 |
| DGIM | 근거 추적 키의 최근 160,000건(약 하루) 기사 중 언급 수 근사 |

### 6-1. 사후 수정: E2 매칭 규칙 (2026-11-17)
